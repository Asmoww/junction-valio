# Decisions

One line each: date, decision, why. Don't reopen without a reason.

- 2026-11-13: Guardrails enforced in the gateway (policy engine), not only in the agent prompt. Why: judged on controls; a jailbroken agent must still be blocked.
- 2026-11-13: Quote-then-commit with quote expiry and idempotency keys. Why: fixed prices, no double orders on retry.
- 2026-11-13: Python 3.12+, FastAPI + Pydantic gateway, Anthropic SDK agent, MCP Python SDK, Jinja/htmx approval UI, SQLite, pytest, uv. Why: one language for the whole team, one process for the demo.
- 2026-11-13: Lookup verifies attributes from structured data (lactose 0 g/100 g, fat %), never from names alone; the shortlist keeps every qualifying product (no cut by name or file order). Why: the old cut dropped the €1.01 milk and overpaid €390 on the demo.
- 2026-11-13: Allergens: CONTAINS a banned allergen blocks; MAY_CONTAIN and missing data follow `allergen_policy` per mandate; missing data is "unknown", never "allergen-free". Why: 46 % of products have no allergen data.
- 2026-11-13: Every offer line carries signed trust flags (stock known?, cut-off, price basis, data gaps, reliability). Why: Valio's "trust protocol" question; agents can't verify claims otherwise.
- 2026-11-13: Unstated details (fat level, fresh vs long-life) are never guessed and never asked in a chat; the agent compares across them and shows the cost of each choice to the approver. Why: "not a chatbot"; one approval instead of two interruptions.
- 2026-11-13: Official substitutes must pass a fit check (same category). Why: Valio's own substitute for coffee milk is cream.
- 2026-11-13: Trap suite (`tests/traps`, `scripts/run_traps.py`) runs real-data cases against the live API; results shown in the Valio view. Why: proof, not claims. Mock quirks documented in `docs/ASSUMPTIONS.md`.
- 2026-11-13: Main repo is Asmoww/hackathon-1 again; `review/rasmus-context` stays a branch, never merged.
- 2026-11-13: Only a signed-in person can approve; an agent's Bearer token gets 403, and the approver must be in the mandate with authority for the total. Why: a hijacked agent must not sign off its own order.
- 2026-11-13: The price lock ends at the earliest of 15 min, any line's order deadline and any line's price validity; an approval after expiry re-checks the price and never places at a stale one. Why: "fixed price" has to stay true until the order is placed.
- 2026-11-13: Stock Valio can't confirm (supplier-warehouse "Terminal" products, or no availability answer) and lactose-free claims backed only by the product name need a person. Valio's own "Stock" products with a placeholder quantity count as confirmed and carry a trust flag (merge decision: otherwise nearly every live order needs a person). Why: the agent must not treat unknowns as facts.
- 2026-11-13: Order lines are validated before pricing (positive, whole units for pieces/boxes, lot size, no duplicates, max 20 lines). Why: a negative line could pull a large order under the auto-approve limit.
- 2026-11-13: Reality check on lookup: Claude sees the matching catalog categories (with sample names) and keeps only those that ARE the requested product, plainest form first (cream, not ice cream; beer, not beer-batter onion rings). It can only narrow results, never add products. No match at all → "not in Valio's catalog", stopped before any API call, with what does exist shown but never ordered. Why: keyword matching can't tell "is" from "contains"; the largest matching category was often the wrong product.
- 2026-11-13: Every dead end gets a specific answer and a next step, never a bare status: unit that doesn't fit the product (1,000 litres of chicken nuggets → sold by kg, "use 1,000 kg"), cheapest option above the hard limit (agent doesn't ask for an offer it knows will be blocked; offers the largest quantity within the limit), and "nothing can be ordered" broken down by reason (deadline passed, unavailable, no price). Suggestions only rewrite the request; nothing is ordered until the person runs it again.
